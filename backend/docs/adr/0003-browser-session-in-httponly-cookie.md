# Browser sessions use HttpOnly cookies

For the HAMS React web client, use a server-managed session sent in a `Secure`, `HttpOnly` cookie rather than exposing a session token to JavaScript and storing it in `localStorage`. This follows OWASP's guidance on browser credential storage and reduces the risk that XSS can export a reusable session token. Bearer tokens may be supported separately if a documented non-browser client needs them.

This choice requires HTTPS, an explicit `SameSite` policy suited to the deployed frontend and API origins, CSRF protection for state-changing requests, an exact CORS origin allowlist, and server-side session expiry and revocation. The React client must send credentialed requests and derive login state from the session endpoint. The web session has a fixed 12-hour absolute lifetime from sign-in and expires after 60 minutes without user-initiated activity; a warning appears five minutes before the inactivity deadline so a user who is still reading can extend it. Background polling and simply leaving a page open do not count as activity, and activity never extends the 12-hour limit. Closing a tab or browser does not sign out while the session is still valid; explicit sign-out revokes the server session and clears its cookie immediately. The 14-day trusted-browser credential only skips TOTP and does not extend the session lifetime. See [OWASP research](../research/browser-auth-storage-owasp.md).
