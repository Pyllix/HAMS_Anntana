# แจ้งผลเครื่องซ่อมไม่ได้หลังพัสดุรับมอบ

เพิ่มเมื่อ 2026-10-16 โดยใช้ Notification API, SSE, กระดิ่ง และสถานะอ่านรายคนชุดเดิม

- เหตุการณ์ `REPAIR_UNREPAIRABLE_RECEIVED` เกิดเมื่อพัสดุยืนยันผ่าน `PATCH /repairs/:id/complete-unrepairable` สำเร็จ
- แจ้งสมาชิก `DEPARTMENT_STAFF` หรือ `ASSET_CENTER_STAFF` ที่ `section_id` ตรงกับ `RepairJob.sectionId` และบัญชียังใช้งานได้ เหมือนแจ้งซ่อมเสร็จเดิม
- ไม่แจ้งตอนวินิจฉัยหรือช่างกดนำส่ง เพราะพัสดุยังไม่ได้ยืนยันรับมอบ
- หัวข้อ “เครื่องซ่อมไม่ได้ พัสดุรับมอบแล้ว” พร้อมเลขใบงาน ชื่อเครื่อง และเลขครุภัณฑ์ถ้ามี
- บันทึกแจ้งเตือนใน transaction เดียวกับการรับมอบ และส่ง SSE หลัง commit เท่านั้น หากบันทึกล้มเหลวให้ rollback ทั้งรายการ
- ใช้ eventKey `REPAIR_UNREPAIRABLE_RECEIVED:<jobId>` และ unique เดิม `(eventKey, userId)` ป้องกันแจ้งซ้ำจากการยืนยันพร้อมกัน
- เมื่อกดแจ้งเตือน FE เปิด `/track-status` และรายละเอียดใบงานเดิม โดยแสดงผลซ่อมไม่ได้ เหตุผล ผู้รับมอบ และวันที่พัสดุรับมอบ
- การรับมอบยังคงปิดใบงานและตั้งเครื่องเป็น `WAIT_DISPOSAL` / `UNAVAILABLE` ตามเดิม

ก่อนเริ่ม BE รุ่นนี้ ให้ใช้ migration `20261015000000_add_unrepairable_receipt_notification` กับฐานข้อมูลเป้าหมาย และสร้าง Prisma Client ใหม่ตามขั้นตอน deploy เดิม

ชุดทดสอบครอบคลุมผู้รับทั้งแผนกและศูนย์ คัดบัญชีที่ระงับ/ลบออก ไม่ส่งข้ามหน่วยงาน ไม่มีเหตุการณ์ก่อนรับมอบ rollback ไม่ส่ง SSE และยืนยันซ้ำไม่สร้างแจ้งเตือนซ้ำ
