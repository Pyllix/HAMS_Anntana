# เตรียมข้อมูลสำหรับนำเสนอ HAMS

ชุดใหม่แยกจาก seed เดิมและสร้างข้อมูลครบใน transaction เดียว ชื่อ รุ่น และรหัสที่แสดงเป็นข้อมูลสมมติในรูปแบบทะเบียนโรงพยาบาล ไม่มีคำว่า Demo หรือชื่อสถานการณ์ทดลองบนหน้าจอ รันซ้ำจะเก็บข้อมูลที่เคยสร้างไว้ ไม่รีเซ็ตสถานะ สต็อก รหัสผ่าน หรือเลขเอกสารหลังซ้อม ศูนย์ครุภัณฑ์ใช้ section code `CENTER` แผนกอื่นใช้รหัสทั่วไป เช่น `ICU`, `ER`, `PARCEL` และ `IT-02` โดย IT ของ reference bootstrap คงอยู่แยกกัน

ข้อมูลนี้เป็น snapshot จำลองของ workflow ที่สัมพันธ์กันครบ ไม่ใช่หลักฐานว่าทุกขั้นถูกเรียกผ่าน HTTP API แล้ว ต้องซ้อมกดต่อผ่าน frontend และตรวจบริการภายนอกก่อนนำเสนอ

มีรายการสดสำหรับเริ่มเรื่องยืม–คืน–แจ้งซ่อม, ใบยืมครบ 8 สถานะ, ต่ออายุออนไลน์/ผ่านศูนย์, คืนปกติ/ชำรุด/ไปรับคืน, เครื่องรุ่นเดียวกันสำหรับแนะนำทั้งกรณีควรสลับและไม่ต้องสลับ, งานซ่อม 4 เส้นทาง, อะไหล่ใน/นอกคลังและผสม, ไม่อนุมัติ/วินิจฉัยใหม่, งานยกเลิก, คืนอะไหล่ และรายการสำหรับเปลี่ยนเป็นสูญหาย

มีความคุ้มค่าซ่อม 7 กรณี ได้แก่คุ้มค่า, เฝ้าระวังค่าใช้จ่าย, ไม่คุ้มค่าใช้จ่าย, ซ่อมถี่, เครื่องเก่า, บริจาคราคา 0 และประกันที่ยังใช้ได้ พร้อมรายการเบิกจริง 18 เดือนที่จบแล้วใน 3 แผนกสำหรับพยากรณ์

บัญชีหลักใช้รหัสพนักงานเดิม `GOV-67....` จาก seed เดิม บัญชีทดลองเพิ่มเติมออกรหัสพนักงานตามปีและต่อจากเลขที่มีอยู่ เลข BR/REP ต่อจากเลขที่มีอยู่โดยใช้รูปแบบเดิม; numeric ID อ่านค่าที่ฐานสร้างจริง ส่วน UUID ของชุดเดโมกำหนดคงที่ตามสถานการณ์เพื่อให้ติดตามและรันซ้ำได้ Manifest บันทึกทั้ง ID และเลขเอกสารจริง ไม่มีรหัสผ่านหรือ secret

## 1. ตรวจชุดข้อมูลโดยไม่ต่อฐาน

```powershell
pnpm run prisma:seed:presentation --dry-run --date 2026-10-09 --output .temp/presentation-plan.json
pnpm run test:presentation
```

`--date` เป็นวันอ้างอิง YYYY-MM-DD หากไม่ระบุจะใช้วันปัจจุบันใน Asia/Bangkok วันที่ยืม/ซ่อม/ประกัน/ประวัติรายเดือนคำนวณสัมพันธ์กับวันนี้ สำหรับเดโมจริงให้ใช้วันใกล้การนำเสนอ

## 2. เตรียมฐานเดโม

สร้าง PostgreSQL database แยกและลง migrations ของโปรเจกต์ก่อน โดยใช้ระบบจัดการฐานที่มีอยู่ อย่าใช้ `prisma:reset` เป็นคำสั่งล้างฐาน: ในโปรเจกต์นี้คำสั่งนั้นลงท้ายด้วย seed เดิมและไม่ได้กู้ snapshot

กำหนด `DEMO_DATABASE_URL` แยกจาก `DATABASE_URL`; สคริปต์นี้ไม่อ่าน `DATABASE_URL` เป็นเป้าหมายโดยอัตโนมัติ รหัสผ่านบัญชีเดโมรับจาก `DEMO_PRESENTATION_PASSWORD` ซึ่งต้องยาวอย่างน้อย 12 ตัวอักษร ให้กำหนดผ่าน environment หรือไฟล์ `.env` ที่ไม่ commit และไม่ใส่รหัสผ่านใน command history

ชื่อฐานควรมี `demo`, `test` หรือ `present` และ `NODE_ENV` ต้องไม่เป็น `production` หากตั้งใจใช้ฐานพัฒนาเดิมที่ชื่อไม่ตรง ต้องเลือก URL อย่างชัดเจนและเพิ่ม `--allow-existing-development` ข้อมูลเดิมไม่ถูกลบ แต่ reference seed อาจปรับชื่อสถานะมาตรฐานตามค่าของโปรเจกต์

สคริปต์ไม่สร้าง database หรือรัน migrations เอง และไม่ติดต่อ SMTP, Gemini หรือ Cloudinary เพื่อใส่ข้อมูลธุรกิจ

### ฐานนำเสนอปัจจุบัน `hams_db_0fl8`

`DATABASE_URL` และ `DEMO_DATABASE_URL` ใน `.env` ใช้ URL ของ `hams_db_0fl8` เดียวกัน โดยชุดนำเสนอสร้างตามวันที่ 2026-10-10 ชื่อฐานนี้ไม่มีคำว่า test/demo/present จึงต้องระบุ `--allow-existing-development` สำหรับคำสั่ง seed และ check:

```powershell
$env:NODE_ENV = 'development'
pnpm run prisma:seed:presentation --allow-existing-development
pnpm run prisma:check:presentation --allow-existing-development
```

รันซ้ำไม่ต้องระบุ `--date` และไม่ต้อง reset การตั้ง 2FA และ session ต้องทำในฐานนี้ผ่านโปรแกรมจริง

### ใช้ฐาน test เดิมและเริ่มจากข้อมูลว่าง

ไม่จำเป็นต้อง reset ก่อน seed: ชุดนำเสนอเพิ่มข้อมูลแยกและรักษาข้อมูลเดิมไว้ แต่ถ้าฐาน test ล้างได้และต้องการให้รายการ/กราฟมีเฉพาะข้อมูลนำเสนอ ให้ reset แล้วลงชุดใหม่นี้เพียงชุดเดียว

ตรวจ `DATABASE_URL` ว่าชี้ฐาน test ที่ต้องการล้าง และตั้ง `DEMO_DATABASE_URL` ให้เป็นฐานเดียวกันก่อนใช้คำสั่งด้านล่าง การ reset ลบข้อมูลทั้งหมดใน schema เป้าหมาย รวมบัญชีเดิม, session และข้อมูล 2FA แล้วลง migrations ใหม่

```powershell
# ใช้โหมด development เฉพาะ terminal นี้ หาก .env ตั้ง production ไว้
$env:NODE_ENV = 'development'
pnpm exec prisma migrate reset --force
pnpm run prisma:generate
pnpm run prisma:seed:presentation
pnpm run prisma:check:presentation
```

รันทีละคำสั่งและหยุดทันทีหากคำสั่งใดล้มเหลว ไม่ใช้ `pnpm run prisma:reset` เพราะสคริปต์ชื่อนี้ไม่ได้ล้างฐานและจะลง seed เดิม หลัง reset ต้องล็อกอินบัญชีนำเสนอใหม่และตั้ง 2FA ใหม่ตามหัวข้อ 6; cookie เดิมใช้ต่อไม่ได้

## 3. สร้างข้อมูลและตรวจความสัมพันธ์

```powershell
pnpm run prisma:seed:presentation
pnpm run prisma:check:presentation
```

อะไหล่มี 20 รายการ: 5 รายการเดิมสำหรับงานซ่อมและ 15 รายการเพิ่มเติม เช่น ผ้าพันแขนวัดความดัน สายลม หัววัดอุณหภูมิ แบตเตอรี่เครื่องให้สารละลาย วาล์ว และฟิวส์ รายการใหม่แต่ละรายการมีรับเข้า 2 ล็อต พร้อมเอกสาร STK ผู้รับเข้า `parcel@hospital.go.th` วันที่ จำนวน และราคารวม หน่วยนับตรงกับอะไหล่ เริ่มสร้างที่ยอด 0 แล้วเพิ่มยอดจากประวัติรับเข้า ส่วนการเบิก/คืนเดิมปรับยอดเฉพาะ INTERNAL ที่ทำจริง

เมื่อรัน `prisma:seed:presentation` บนฐานที่มีชุดนำเสนอเดิม จะเติมเฉพาะอะไหล่ที่ยังไม่มีใน manifest พร้อมประวัติรับเข้า โดยไม่รีเซ็ต 5 รายการเดิม งานซ่อม หรือประวัติการเบิก/คืน รันซ้ำไม่เพิ่มยอดหรือล็อตซ้ำ คำสั่ง `prisma:check:presentation` อ่านและตรวจอย่างเดียว ไม่เติมข้อมูล ใช้ `parcel@hospital.go.th` เปิดรายการอะไหล่และประวัติรับเข้าเพื่อสาธิต แล้วทดลองรับเข้าล็อตใหม่ผ่านหน้าจอได้

ข้อมูลที่ใช้ ID หรือรหัสของชุดนี้อยู่แล้วแต่ไม่มี marker ที่สมบูรณ์จะทำให้สคริปต์หยุด แทนการยึดหรือเขียนทับข้อมูลนั้น เก็บ marker บริษัท `HAMS-PRESENT-V1` ไว้ เพราะใช้จำว่าชุดนี้สร้างครบแล้ว

ผลลัพธ์อยู่ที่ `.temp/presentation-manifest.json` มีชื่อสถานการณ์, ID, เลขทะเบียน/เอกสาร และสถานะตอนเตรียม หากนำรายการไปดำเนินการสดแล้ว สถานะที่บันทึกใน manifest เป็นจุดเริ่มต้น ใช้ API/UI ดูสถานะปัจจุบัน ส่วนคำสั่ง check จะตรวจข้อมูลจริงรวมรายการใหม่ของเครื่องในชุดนี้

รันซ้ำโดยไม่ระบุวันใหม่จะใช้ชุดเดิม ถ้ากำหนด `--date` ต่างจากชุดเดิม สคริปต์หยุดและให้เลือกฐานใหม่หรือกู้ snapshot ที่ตั้งใจใช้ ห้ามรัน seed เดิมทับชุดที่นำเสนอไปแล้ว เพราะ seed เดิมอาจย้อนสถานะ/ยอดคงเหลือ

สำหรับฐานที่เคยลงชุด `present-*` เวอร์ชันก่อน ใช้คำสั่งนี้เพื่อเปลี่ยนบัญชีครั้งเดียวโดยรักษา ID และข้อมูลธุรกิจไว้:

```powershell
pnpm run prisma:seed:presentation --restore-original-users
```

คำสั่งนี้เปลี่ยนบัญชีหลักเป็นข้อมูลและรหัสผ่านตั้งต้นของ seed เดิมโดยตรง และเพิ่มบัญชีเดิมที่ขาด หลังเปลี่ยนครั้งแรกแล้วรันซ้ำจะไม่รีเซ็ตรหัสผ่าน การ seed ลงฐานว่างจะใช้บัญชีเดิมตั้งแต่ต้นโดยไม่ต้องใส่ flag นี้

หากฐานเคยลงชุดที่ใช้ section code `PRESENT-CENTER` หน้ารายการพร้อมยืมจะไม่พบศูนย์และ API ยืมจะปฏิเสธเครื่องใน section นี้ แก้เฉพาะรหัสศูนย์โดยคง section ID และ FK ทุกตัวด้วย:

pnpm run prisma:seed:presentation --repair-center-section --check

## 6. สิ่งที่ต้องเตรียมผ่านระบบจริง

1. ตั้ง 2FA ให้ admin, admin_backup, assetcenter และ parcel ผ่าน enrollment/ยืนยัน TOTP/รับ Recovery Code/ยืนยันจัดเก็บ แล้วล็อกอินแต่ละ browser Profile ล่วงหน้า อย่าใส่ secret/session/TrustedDevice ปลอมเพื่อข้าม guard
2. เก็บ parcel2 (key parcel-enroll) ไว้สาธิต enrollment ใหม่; การ reset 2FA ต้องมี ADMIN อีกคนพร้อม Step-up และรักษาเงื่อนไข ADMIN ที่ enroll คนสุดท้าย
3. อีเมล seed ทั้ง `hospital.go.th` และ `.local` เป็นบัญชีตัวอย่าง ให้ใช้ SMTP capture เช่น Mailpit ไม่ควรถือว่าเป็นกล่องที่เราควบคุมได้ หากจะส่งจริงให้เปลี่ยนบัญชีทดลองผ่านขั้นตอนปกติและใช้กล่องที่ควบคุมได้
4. รูป asset ใช้ URL ตัวอย่าง Unsplash จาก seed เดิม โดยตรง ไม่ต้องอัปโหลดและไม่สร้าง metadata ของ Cloudinary รูปเป็นภาพประกอบตัวอย่างและต้องมีอินเทอร์เน็ต สำหรับสาธิตฟีเจอร์อัปโหลดจริงหรือรูปพนักงานที่อ่านแบบมีสิทธิ์ จึงค่อยเตรียม PNG/JPEG แล้วอัปโหลด/complete/ผูก imageUploadId ผ่านโปรแกรม
5. ตรวจการอ่านรูปพนักงานหลังล็อกอิน, preview และเปลี่ยนรูป ตรวจ Cloudinary, SMTP และ `GEMINI_API_KEY` กับ model/เครือข่ายจริงก่อนเดโม
6. Trusted browser ต้องเกิดจากการเลือกเชื่อถือใน browser จริง ส่วน revoke/Recovery/เปลี่ยนรหัสผ่าน/เปลี่ยน role ทำกับบัญชีทดลอง เพราะอาจทำให้ session ใช้งานต่อไม่ได้

## 7. การตรวจและเริ่มใหม่

คำสั่ง check ตรวจสถานะเครื่องเทียบกับ active loan/repair, ลำดับวันที่/ขั้นตอน, assignment, stock ledger, การคืนไม่เกินเบิก, extension, disposal และแผนกหลังโอน พร้อมแจ้งบัญชีที่ยังต้องตั้ง 2FA/รูปที่ยังไม่ผูก เป็นการตรวจข้อมูล ไม่ได้เรียกบริการภายนอกหรือยืนยันหน้าจอ frontend

หากต้องการกลับมาซ้อมด้วยเลขและสถานะเดิม ให้กู้ snapshot ฐานเดโมที่เตรียมไว้ โดยจัดการ cookie/login ใหม่ตามจริง การ rerun สคริปต์นี้ตั้งใจรักษาสถานะปัจจุบันและไม่ใช่คำสั่ง reset

ไม่ควรสาธิตลบ marker/ข้อมูลที่ชุดเดโมใช้อ้างอิง ให้ใช้ record สำหรับทดลองโดยเฉพาะ การเพิ่ม seed ไม่ได้เพิ่มฟีเจอร์ตรวจนับ/ใบสั่งซื้อเต็มรูปแบบ/notification/API ที่ยังไม่มี

## เติมรูป asset ตัวอย่างโดยไม่อัปโหลด

ฐานที่เคยลงชุดนำเสนอแบบรูปว่าง ใช้คำสั่งนี้ (หลังเลือก `DEMO_DATABASE_URL` และโหมด development):

```powershell
pnpm run prisma:seed:presentation --sample-asset-images --check
```

คำสั่งเติมเฉพาะ `imageUrl` ของเครื่องในชุดนำเสนอที่รูปว่างและไม่มี managed image locator ไม่ทับ URL ที่มีอยู่หรือรูปที่อัปโหลดจริง ไม่เรียก Cloudinary หรือบริการสร้างภาพ และไม่เปลี่ยน ID/section/สถานะ/ใบยืม/งานซ่อม ฐานว่างที่ seed ใหม่จะได้ URL ตัวอย่างตั้งแต่ต้น

## เปลี่ยนข้อความจากชุดเก่าให้เหมือนทะเบียนโรงพยาบาล

```powershell
pnpm run prisma:seed:presentation --natural-labels --check
```

เปลี่ยนชื่อ/รุ่น/ทะเบียน/serial ของครุภัณฑ์ ชื่อแผนก บริษัท อะไหล่ งบ และข้อความประกอบที่มาจากชุดเก่า โดยรักษา UUID/numeric ID, FK, สถานะ, วันทำรายการ, ค่าใช้จ่าย, ยอดสต็อก, รูป และรหัสผ่าน เครื่องที่เคยเป็นรุ่นเดียวกันยังเป็นรุ่นเดียวกันเพื่อรักษาผลของฟีเจอร์แนะนำเครื่อง เลข BR/REP เดิมยังคงอยู่ รหัสเอกสารที่เคยขึ้นต้น DEMO ของการโอน/จำหน่าย/รับอะไหล่เปลี่ยนเป็นรูปแบบ TF/DSP/STK

คำสั่งนี้ทำครั้งเดียวและรันซ้ำจะรักษาชื่อที่แก้หลังจากนั้นไว้ ส่วนการ seed ฐานว่างใช้ป้ายชื่อใหม่ตั้งแต่ต้น อ่านเลขทะเบียนใหม่จาก manifest ที่อัปเดตแทนการจำเลขเก่า ระบบยังเก็บ key ของสถานการณ์และ marker `HAMS-PRESENT-V1` ภายในเพื่อให้รันซ้ำได้ อย่าลบ marker หรือแก้ ID เพื่อเปลี่ยนชื่อ
